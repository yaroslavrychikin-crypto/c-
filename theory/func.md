# Функции и контракт параметров в C++ — гайд для начинающих

## Введение

Ты уже знаешь типы данных, `if`, `for`, `while`. Теперь пора узнать про **функции** — это твой главный инструмент, чтобы не писать один и тот же код по десять раз.

**Функция** — это именованный блок кода, который выполняет одну задачу. Ты даёшь ему имя, а потом «вызываешь» по имени, когда нужно.

**Контракт параметров** — это договор: что функция ждёт на входе, что она вернёт и что она **не будет делать**. Как в рецепте: «возьми 2 яйца — получишь омлет». Если дать 5 яиц — это уже нарушение контракта.

---

## 1. Declaration / Definition — объявление и определение

Функция состоит из двух частей.

### Объявление (declaration) — «визитка»

Здесь написано **имя, что принимает и что возвращает**, но нет тела. Это как оглавление книги: ты знаешь, что глава есть, но ещё не читал её.

```cpp
int add(int a, int b);          // объявление: "есть функция add, принимает 2 int, вернёт int"
double area(double radius);     // объявление
```

### Определение (definition) — «сама глава»

Здесь есть **тело** — что функция реально делает.

```cpp
int add(int a, int b) {         // определение
    return a + b;
}

double area(double radius) {    // определение
    return 3.14159 * radius * radius;
}
```

### Зачем нужны обе части?

Компилятор читает код **сверху вниз**. Если ты вызовешь функцию до того, как её описал, он скажет «не знаю такую». Объявление заранее говорит: «такая функция будет, поверь».

```cpp
int square(int x);   // объявление заранее

int main() {
    int result = square(5);   // OK — компилятор уже знает про square
    return 0;
}

int square(int x) {           // определение ниже
    return x * x;
}
```

**Правило простое:** объявление можно писать сколько угодно раз, а определение — **только один раз**.

## 2. `return` — возврат значения

`return` говорит: «функция закончила работу, вот её результат». После `return` код в функции **не выполняется**.

```cpp
int max(int a, int b) {
    if (a > b) {
        return a;      // если a больше — выходим здесь
    }
    return b;          // иначе выходим здесь
}
```

### Главные правила

**1. Функция, которая что-то возвращает, обязана вернуть значение на всех путях.**

```cpp
int bad(int x) {
    if (x > 0) {
        return 1;
    }
    // ❌ если x <= 0 — что вернуть? Компилятор будет ругаться
}
```

Правильно:

```cpp
int good(int x) {
    if (x > 0) {
        return 1;
    }
    return 0;          // ✅ все пути покрыты
}
```

**2. `void`-функция ничего не возвращает.** `return;` просто завершает её досрочно.

```cpp
void print_hello() {
    std::cout << "Hello!\n";
    return;            // можно, но не обязательно
}

void check(int x) {
    if (x < 0) {
        std::cout << "Negative!\n";
        return;        // досрочный выход
    }
    std::cout << "OK\n";
}
```

**3. Не возвращай адрес локальной переменной!** Локальная переменная умирает, когда функция заканчивается, и адрес становится «мусорным» (это называется undefined behavior — программа может сделать что угодно).

```cpp
int* bad() {
    int x = 42;
    return &x;         // ❌ x умрёт, указатель станет мусором
}
```

**4. `[[nodiscard]]`** — если пометить функцию так, компилятор предупредит, когда ты забудешь использовать результат.

```cpp
[[nodiscard]] int compute();

compute();  // ⚠️ warning: результат проигнорирован
int x = compute();  // OK
```

## 3. Pass by value — передача по значению

Параметр **передаётся в функцию как значение**. Это самый простой и безопасный способ: функция получает своё значение и работает с ним, не трогая оригинал.

```cpp
void increment(int x) {
    ++x;               // меняем только локальное значение
}

int main() {
    int a = 5;
    increment(a);
    // a осталось 5!
}
```

Почему? Потому что `x` внутри функции — это **отдельное значение**, в которое попал `a`. Меняешь `x` — оригинал не трогаешь.

### Когда использовать pass by value

- Для **маленьких типов**: `int`, `double`, `char`, `bool`.
- Когда функции **не нужно менять** аргумент.
- Когда ты **не хочешь**, чтобы функция меняла твою переменную.
- Когда функции нужно **собственное значение**, независимое от оригинала.

### Цена передачи больших объектов

Для маленьких типов (`int`, `double`) передача по значению — это мгновенно. А вот для больших объектов (например, длинных строк) передача по значению может быть **дорогой**: нужно передать всё содержимое.

```cpp
void print_big(std::string text) {   // ⚠️ передаётся вся строка
    std::cout << text;
}

std::string huge = "...очень длинная строка...";
print_big(huge);                     // дорого для большой строки
```

В таких случаях на помощь приходит `std::string_view` (см. раздел 4).

## 4. `std::string_view` — «посмотреть на строку без передачи владения»

Иногда функция только **читает** строку и ничего менять не собирается. Передавать целую строку ради того, чтобы её напечатать, — расточительно.

Для этого есть **невладеющий просмотр** — он смотрит на строку, но не владеет ею.

```cpp
#include <string_view>

void print(std::string_view s) {
    std::cout << s;      // ✅ читаем
    // s[0] = 'X';       // ❌ ошибка компиляции — только чтение
}

int main() {
    std::string huge = "...длинная строка...";
    print(huge);         // быстро — без передачи владения
    print("hello");      // работает и с литералами
}
```

### Контракт `string_view`

- **Не владеет** данными — быстро.
- **Не меняет** данные — только чтение.
- Данные должны жить, пока ты на них смотришь.

⚠️ **Главная ловушка:** не сохраняй `string_view` дольше, чем живёт исходная строка. Если строка умрёт, `string_view` будет смотреть в пустоту.

```cpp
std::string_view bad() {
    std::string s = "hello";
    return s;            // ❌ s умрёт, string_view станет мусором
}
```

### Когда использовать

- Функция **только читает** строку.
- Ты **не хочешь передавать владение** данными.

### Когда НЕ использовать

- Для маленьких типов (`int`, `double`) — pass by value проще.
- Когда функция должна **менять** строку — тогда передавай по ссылке.
- Когда функция должна **забрать владение** — тогда pass by value + `std::move`.

## 5. Default argument — аргумент по умолчанию

Иногда параметр почти всегда имеет одно и то же значение. Вместо того чтобы писать его каждый раз, можно задать **значение по умолчанию**.

```cpp
void log(std::string msg, int level = 1, bool timestamp = false);

log("start");                 // level=1, timestamp=false — по умолчанию
log("err", 3);                // level=3, timestamp=false
log("dbg", 2, true);          // level=2, timestamp=true
```

Это как в кафе: «кофе» — по умолчанию средний размер. Но можно сказать «большой».

### Правила

**1. Default-аргументы идут справа налево.** После первого «значения по умолчанию» все следующие тоже должны иметь default.

```cpp
void f(int a, int b = 0, int c);   // ❌ ошибка: c без default после b с default
void f(int a, int b = 0, int c = 0); // ✅ OK
```

Почему? Потому что когда ты вызываешь `f(1, 2)`, компилятор не знает, что `2` — это `b` или `c`.

**2. Default указывается только в объявлении, не в определении.**

```cpp
// .h (заголовок)
void f(int a, int b = 10);

// .cpp (реализация)
void f(int a, int b) {    // без "= 10"!
    // ...
}
```

### Подводные камни

**Виртуальные функции** — default-аргументы берутся из **статического** типа, а не из динамического. Это классическая ловушка:

```cpp
struct Base { virtual void f(int x = 1); };
struct Derived : Base { void f(int x = 2) override; };

Base* p = new Derived;
p->f();   // вызовется Derived::f, но с x = 1 (!) — сюрприз
```

**Магические флаги** — не делай так:

```cpp
void process(int x, bool flag = false);   // ❌ что значит flag?
```

Лучше `enum class` или отдельные функции с понятными именами:

```cpp
enum class Mode { Fast, Safe };
void process(int x, Mode mode = Mode::Safe);   // ✅ понятно
```

## 6. Pure function — чистая функция

**Чистая функция** — это функция, которая:

1. **Возвращает результат, зависящий только от аргументов** (одинаковый вход → одинаковый выход).
2. **Не имеет побочных эффектов** — не меняет глобальные переменные, не пишет в консоль, не трогает файлы.

### Примеры

```cpp
int add(int a, int b) { return a + b; }               // ✅ чистая
int abs(int x) { return x < 0 ? -x : x; }             // ✅ чистая
int square(int x) { return x * x; }                   // ✅ чистая

int counter = 0;
int next_id() { return ++counter; }                    // ❌ побочный эффект — меняет counter

void print_sum(int a, int b) {
    std::cout << a + b;                                // ❌ побочный эффект — пишет в консоль
}
```

### Почему чистые функции — это круто

**1. Легко тестировать.** Не нужно ничего настраивать — просто вызвал и проверил результат.

```cpp
assert(square(5) == 25);
assert(square(-3) == 9);
assert(add(2, 3) == 5);
```

**2. Легко понять.** Функция не зависит от того, что происходит в других местах программы.

**3. Безопасно для параллельности.** Две чистые функции можно запустить одновременно — они не будут мешать друг другу.

**4. Компилятор может оптимизировать.** Если результат уже известен, он может посчитать его заранее.

### Как сделать функцию чистой

**Убирай побочные эффекты.** Вместо того чтобы печатать внутри — возвращай результат, а печатай снаружи.

```cpp
// ❌ нечистая: печатает внутри
void print_average(int a, int b, int c) {
    std::cout << "avg = " << (a + b + c) / 3.0;
}

// ✅ чистая: возвращает результат
double average(int a, int b, int c) {
    return (a + b + c) / 3.0;
}

// печать — отдельно, на границе программы
int main() {
    std::cout << "avg = " << average(10, 20, 30);   // I/O только здесь
}
```

**Помечай `constexpr`,** если функция может вычислиться на этапе компиляции:

```cpp
constexpr int square(int x) { return x * x; }
static_assert(square(5) == 25);   // проверяется ещё до запуска программы
```

### Практика

Старайся, чтобы **вся логика** была в чистых функциях, а ввод-вывод и работа с файлами — только на «границе» программы (в `main` или в отдельной функции).

## 7. Как выразить контракт в C++

C++ не имеет специального слова «contract». Но есть инструменты, которые помогают **явно показать**, что функция обещает.

| Инструмент | Что обещает |
|---|---|
| `int x` (by value) | работает с отдельным значением, оригинал не меняется |
| `std::string_view` | не владеет, не меняет данные |
| `[[nodiscard]]` | результат важен, не игнорируй |
| `noexcept` | не бросает исключений |
| `constexpr` | вычисляется на этапе компиляции |
| `std::optional<T>` | «может не быть значения» |
| `enum class` | явные допустимые значения вместо `bool`/`int` |

Пример явного контракта в комментарии:

```cpp
// Precondition: 0 <= index < length
// Postcondition: возвращает элемент, не меняет данные
[[nodiscard]] int at(int index) const;
```

**Precondition** — что должно быть верно **до** вызова.
**Postcondition** — что функция гарантирует **после** вызова.

## Задача: разбить монолитный обработчик на функции с явными контрактами

### Исходный код (монолит)

Представь, что у тебя есть программа, которая получает **одну строку** вида `"Alice,25"` и печатает отчёт. Всё в одной функции:

```cpp
#include <iostream>
#include <string>

void process_user(std::string raw) {
    auto pos = raw.find(',');
    if (pos == std::string::npos) {
        std::cerr << "bad line: " << raw << "\n";
        return;
    }

    std::string name = raw.substr(0, pos);
    int age = 0;
    try {
        age = std::stoi(raw.substr(pos + 1));
    } catch (...) {
        std::cerr << "bad age: " << raw << "\n";
        return;
    }

    if (name.empty() || age < 0 || age > 150) {
        std::cerr << "invalid user: " << raw << "\n";
        return;
    }

    // проверка: совершеннолетний?
    bool adult = age >= 18;

    std::cout << "name=" << name << "\n";
    std::cout << "age=" << age << "\n";
    std::cout << "adult=" << (adult ? "yes" : "no") << "\n";
}
```

### Проблемы монолита

- **Всё смешано:** разбор строки, проверка, вычисление, печать.
- **Непонятно, что считается ошибкой:** какая строка «плохая»? Что делать с ошибками?
- **Невозможно протестировать по частям:** чтобы проверить парсинг, нужно запустить всю программу.
- **Печать размазана по коду:** `std::cout` и `std::cerr` в разных местах.

---

### Решение: разбиваем на функции

```cpp
#include <iostream>
#include <string>
#include <string_view>
#include <optional>

// ── 1. Разобрать одну запись "name,age" ─────────────────
// Контракт: вход — строка "name,age".
// Возвращает true при успехе (name/age заполнены) или false при ошибке.
// Не печатает, не бросает — чистая функция.
[[nodiscard]] bool parse_user(std::string_view line,
                              std::string& name, int& age) {
    const auto comma = line.find(',');
    if (comma == std::string_view::npos) return false;

    const auto name_part = line.substr(0, comma);
    const auto age_part = line.substr(comma + 1);
    if (name_part.empty() || age_part.empty()) return false;

    int parsed_age = 0;
    try {
        parsed_age = std::stoi(std::string(age_part));
    } catch (...) {
        return false;
    }
    if (parsed_age < 0 || parsed_age > 150) return false;

    name = std::string(name_part);
    age = parsed_age;
    return true;
}

// ── 2. Проверить, совершеннолетний ли ───────────────────
// Контракт: age >= 0. Чистая функция, ничего не печатает.
[[nodiscard]] bool is_adult(int age) noexcept {
    return age >= 18;
}

// ── 3. Напечатать отчёт ──────────────────────────────────
// Контракт: печатает отчёт в os. Единственная функция с I/O.
void print_report(const std::string& name, int age, std::ostream& os) {
    os << "name=" << name << "\n";
    os << "age=" << age << "\n";
    os << "adult=" << (is_adult(age) ? "yes" : "no") << "\n";
}

// ── 4. Главная функция — связывает всё вместе ───────────
// Контракт: разбирает строку, печатает ошибку или отчёт.
void process_user(std::string_view raw) {
    std::string name;
    int age = 0;

    if (!parse_user(raw, name, age)) {
        std::cerr << "bad line: " << raw << "\n";
        return;
    }

    print_report(name, age, std::cout);
}
```

### Что стало лучше

| Было (монолит) | Стало (разбили) |
|---|---|
| Всё в одной функции — тяжело читать | Каждая функция делает одно дело |
| Непонятно, что считается ошибкой | `parse_user` возвращает `bool` — явный контракт |
| `cout`/`cerr` везде | I/O только в `print_report` и `process_user` |
| Нельзя протестировать парсинг | `parse_user` и `is_adult` — чистые, тестируются легко |
| Нельзя переиспользовать | Каждую функцию можно вызвать отдельно |

### Мини-тесты (проверка контрактов)

```cpp
#include <cassert>

int main() {
    // parse_user — чистая функция, проверяем без I/O
    std::string name;
    int age = 0;

    assert(!parse_user("bad", name, age));           // нет запятой
    assert(!parse_user(",25", name, age));            // пустое имя
    assert(!parse_user("Bob,abc", name, age));        // не число
    assert(!parse_user("Bob,-1", name, age));         // отрицательный возраст
    assert(!parse_user("Bob,200", name, age));        // слишком большой

    assert(parse_user("Bob,25", name, age));          // OK
    assert(name == "Bob");
    assert(age == 25);

    // is_adult — чистая функция
    assert(!is_adult(17));
    assert(is_adult(18));
    assert(is_adult(100));
}
```

### Задание читателю

1. **Добавь `trim`** — функцию, которая убирает пробелы в начале и конце строки. Сделай её чистой: принимает `string_view`, возвращает `string_view`.
2. **Добавь функцию `category(age)`** — возвращает `"child"`, `"adult"` или `"senior"`. Чистая, тестируется отдельно.
3. **Покрой тестами** `parse_user` и `is_adult` — не трогая `std::cout`.

## Итог: чек-лист контракта функции

Перед тем как написать функцию, ответь себе на вопросы:

- [ ] **Что функция принимает?** Какие значения допустимы? (preconditions)
- [ ] **Что она возвращает?** Что значит «нет результата» — `optional`, `bool` + выходной параметр или исключение?
- [ ] **Есть ли побочные эффекты?** Печатает? Меняет глобальные переменные? Можно ли вынести в отдельную функцию?
- [ ] **Может ли она быть чистой?** Если да — сделай чистой и `constexpr`.
- [ ] **Нужны ли default-аргументы?** Или лучше `enum class` или перегрузки?
- [ ] **Результат важен?** Помечай `[[nodiscard]]`.

**Главная мысль:** маленькая функция с понятным контрактом лучше большой функции, которая делает всё сразу. Разбивай, называй понятно, документируй, что ожидаешь и что гарантируешь.
